# Projeto Shopee — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trazer para o painel os dados da Shopee equivalentes aos do Mercado Livre (o que a API oferecer), com visões Geral, Individual e Comparativa, crescimento contra o período anterior e o ano passado, e sugestão por canal com percentuais editáveis.

**Architecture:** Reaproveita a estrutura do Mercado Livre: mesmas tabelas com canal `shopee`, conector somente leitura em `packages/connectors/src/shopee/`, sincronização no job existente (`jobs/src/index.ts`, fonte própria), token guardado como o do Mercado Livre (`core.oauth_tokens` + `jobs/src/token-store.ts`). Tarifas e frete da Shopee vêm do detalhe de pagamento (escrow) de cada pedido, numa tabela própria que faz para a Shopee o papel de `analytics.ml_fatura`. Nada de sistema paralelo.

**Tech Stack:** TypeScript (conector, job, rotas Next.js), Postgres/Supabase (funções `analytics.*`, testes com PGlite), Next.js (telas), GitHub Actions (sincronização).

**Spec:** `docs/superpowers/specs/2026-11-24-shopee-design.md`

**Ramo:** `003-shopee`, criado a partir do `main`. Nada vai ao `main` nem ao GitHub sem autorização do dono, a cada vez.

## Global Constraints

- Conexão Shopee somente leitura: nenhuma chamada de escrita à API (preço, estoque, anúncio).
- Credenciais da Shopee (partner id, partner key, código de autorização, tokens) só em GitHub Secrets, variáveis de servidor da Vercel e no banco criptografado (`core.save_oauth_tokens`). Nunca no código, no chat, em arquivos do projeto ou nos logs.
- Migrations reexecutáveis, numeradas a partir de `0020` (0014–0017 são do ramo `001-catalogo-produtos`): `0020_shopee_pagamentos.sql`, `0021_shopee_funcoes.sql`, `0022_crescimento_canal.sql`.
- Funções `analytics.*` com `security invoker`, exceto as que devolvem agregados para quem tem `ads` (`security definer` com `revoke ... from public, anon` e `grant ... to authenticated`, como `ads_seguidores`).
- Custos, tarifas e margem só para quem tem `custos`.
- Testes SQL com PGlite (`npm run test:sql`, cada suíte nova registrada no script); testes TypeScript com `node --test` (`npm run test:web`).
- Commits em português, terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (ou o modelo em uso).

## Review Focus

1. Pedido da Shopee sem itens, cancelado ou com status novo: o painel não pode quebrar nem somar errado.
2. Token expirado, refresh recusado ou autorização vencida (30 dias sem sincronizar): a sincronização da Shopee falha de forma visível, pede "reconecte a Shopee" e não derruba o Mercado Livre na mesma execução.
3. Pedido sem escrow ainda (pagamento não liberado): tarifa e frete entram como estimados e marcados, não zerados; a margem não sai inflada.
4. Anúncio da Shopee sem SKU equivalente ao modelo do ERP: aparece como "sem modelo", e a soma da tabela continua batendo com o cartão.
5. Período sem dados da Shopee (antes da primeira sincronização): as visões mostram "sem dados", não zero que parece real.
